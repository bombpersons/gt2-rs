# Automatic licence replay recording

`race::replay_recording` records live digital driver requests into native
`ReplayClip` runs. Ordinary licence participants receive a `ReplayRecorder`
when the optional recording settings are available. Imported replay cars do
not record again. The rules plugin runs before driver input processing and
emits one `ReplayRecordingFinished` event when recording closes. Mods can use
the public recorder and native clip without original assets.

The original packet format remains an offline import concern. Runtime state
contains named requests, run durations and a storage budget; it does not write
or interpret original packets. `race/replay-recording.ron`, generated by the
normal asset exporter, supplies capacity, closing reserve and post-result wait.

## Writer and lifecycle evidence

The original writer at `800166CC` increments total duration before deciding
whether a changed request flushes its predecessor. `80016598` flushes a run;
`800166AC..6C0` closes storage when its used size reaches capacity minus the
closing reserve. Setup at `80012EC0` allocates the recording capacity. The
native storage count follows these observed rules:

- The first digital run costs five bytes; subsequent changed-button runs
  cost two, before duration extensions.
- A run's repeat count is its duration minus one. Extension sizes change at
  repeat counts 8, 1,024, 131,072 and 16,777,216.
- Opposing steering or shift requests still change storage even when their
  normalized driving request cancels. Recording therefore retains the
  separate held requests for its budget and coalesces effective controls in
  the native clip.
- A capacity-closing flush counts the next request but never serializes it.
  The native clip retains this terminal sample; playback discards it under
  the already verified decrement-before-input rule. The offline importer
  accepts that specific one-sample duration discrepancy only at the capacity
  boundary with the observed pending counter.
- Normal finalization at `800167D0` flushes the pending run. Cancellation
  skips that flush and exposes no playback clip. Closed recordings remain
  immutable; empty recordings expose no clip.

The licence gate at `80013D78..98` ends recording at sixty post-result fields.
The outcome latch initializes elapsed time to one native tick
(`80029C84..CBC`), and the next driver call advances it before testing the gate
(`80015D00..18`). Consequently, the recorder accepts 28 further requests after
the finish tick, then finalizes. The result screen's accelerated wait is an
independent clock. Both successful and failed natural attempts verify this
ordering.

## Executed checks

`tools/record_replay_recording.py` observes original writer/finalizer entries,
returns and memory writes under `psx 0.4.2+src-4c4c84345897a7b9-release`.
Expected durations, storage sizes, closure and pending durations come from
execution, not a duplicate codec. Every retained report has complete watches
and no dropped trace lines. Commands, build identity and source checkpoint
digest accompany the ignored reference data.

Nineteen initial cases cover 2,729 calls: natural success/failure, seven small
capacities, eight duration-extension boundaries, cancellation and an empty
recording. Long holds seed an existing pending run to exercise the unchanged
writer without simulating millions of idle ticks. Capacity probes change only
the buffer limit; cancellation probes change the caller's discard argument
at `80013D9C`, rather than claiming coverage of the unported quit menu.
Six later holdouts add
1,463 calls with a different natural attempt, four capacities, simultaneous
opposed inputs and cancellation. Native recording and the natural lifecycle
bridge match every observed state exactly. Imported native clips also match
every emitted control run.

A further 17,600-field run fills the real buffer with alternating held inputs.
All 8,801 writer calls match; closure occurs at 8,712 counted ticks and
17,391 used bytes. Its 746,353 watched writes are complete, with no dropped
trace lines. This checks the actual capacity in addition to reduced limits.
The first stress capture exhausted the observation budget and was rejected;
the retained run raises that budget and verifies completeness explicitly.

Three capacity-closed recordings additionally execute through the original
decoder for nineteen calls. Native playback matches their output controls,
remaining durations, hold counters and neutral terminal calls.

The actual native binary records a complete B-1 attempt through its normal
countdown and vehicle rules. At tick 1,250 it has the original 38.675-second
pass, a closed 1,247-tick track and the same twelve-byte storage count. The
track equals the source's imported clip: two idle ticks, 1,105 throttle ticks
and 140 brake ticks. Its rendered Finish screen was inspected. The handmade
example mod still drives its own car/course through the public game APIs.

Reproduction uses the current-core countdown checkpoint described in
[session export evidence](session-start-evidence.md#default-scene-export).
Older emulator save-state formats must be rebuilt from power-on:

```sh
python3 tools/record_replay_recording.py
python3 tools/record_replay_recording.py --fresh
python3 tools/record_replay_recording.py --full-capacity
cargo test -p gran_turismo_2 --all-features --test replay_recording --test replay
cargo test -p gran_turismo_2 --all-features --test dev_mcp native_licence_attempt_records -- --ignored
```

## Remaining replay work

This establishes live digital recording and its storage/end boundaries.
`LicenceReplayRequested` still needs the automatic session/car reset and
attachment of the just-completed track. Replay cameras/HUD, pause/exit, return
and award commit, retry, name entry and persistent replay/save files remain.
Analog/special input producers remain unported and the original importer
rejects their selectors explicitly.
